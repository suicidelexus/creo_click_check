# ClickTag Cleaner — редизайн интерфейса

**Дата:** 2026-06-30
**Статус:** дизайн утверждён, готов к плану реализации

## Контекст и цель

`creo_click_check` (он же ClickTag Cleaner) — сервис, который принимает ZIP-архивы
с HTML5-креативами и вырезает из них кликовую логику (переходы по клику на баннер).

**Важное уточнение назначения** (текущие README и тексты UI это описывают неверно):
креативы **приходят с Яндекса** с зашитой кликовой логикой, а чистятся для заливки
в **программатик-DSP, в частности Hybrid DSP**, у которого в технических требованиях
прописано: в HTML5 не должно быть событий, отрабатывающих переход при клике на баннер.
То есть инструмент готовит креативы **под требования DSP**, а не «для Яндекса».

**Цель редизайна:** превратить текущий дефолтный GitHub-dark одностраничник
(«детская хуета») в серьёзный продуктовый инструмент — красивый и с удобным флоу.

**Референс стиля:** дашборд FocusFlow — светлая тема, мягкий фон, белые карточки
с большими скруглениями и мягкими тенями, индиго primary, салатово-лаймовый акцент,
пилюли-чипсы. Адаптировано под одно-функциональный инструмент (НЕ многопанельный
дашборд).

## Границы работы

**Меняем — только фронтенд:**
- `public/index.html` — новая двухпанельная разметка + вшитые инлайн-SVG иконки.
- `public/style.css` — новая светлая дизайн-система целиком.
- `public/app.js` — переписать рендер под две панели (список ↔ деталь), выбор
  активного элемента, инлайн-ошибки, скелетоны. Слой общения с API не меняется.
- Тексты заголовка/сабтайтла/футера — поправить на DSP-формулировку.

**НЕ трогаем:** `server.js`, `src/cleaner/*`, `tests/*`, `package.json`.
Контракт API остаётся прежним. Деплой на Render (`npm start`, Express отдаёт статику
из `public/` + API) — без изменений. Никаких новых зависимостей и билд-шагов.

## Контракт API (используется фронтом, не меняется)

- `POST /api/clean` (multipart, поле `files`, до 50 zip) →
  `{ batchId, bulkDownloadUrl, results: [...] }`. Весь батч возвращается одним
  ответом (не стримится).
- Каждый элемент `results`:
  - `id`, `originalName`, `cleanedName`, `bytesIn`, `bytesOut`
  - `error` (если архив не обработан)
  - `downloadUrl`, `previewUrl`, `originalPreviewUrl`, `primaryHtml`
  - `adSize: { width, height }` (может отсутствовать → дефолт 320×480)
  - `textFiles: [{ path, kind, bytes, originalUrl, cleanedUrl }]`
  - `report: { totalFiles, htmlFiles, jsFiles, cssFiles, primaryHtml, adSize,
    changes: [{ file, kind, actions[], warning, error }] }`
- `GET /api/download/:batchId/:archiveId` — один очищенный архив.
- `GET /api/download-all/:batchId` — весь батч одним zip.
- `GET /api/preview[-original]/:batchId/:archiveId/*` — файлы для iframe-превью.

## Визуальная система

- **Фон:** бело-мятный базовый (`#f4faf6`-зона) + полупрозрачная фоновая картинка
  `public/assets/bg-creo.png` (лайм-стекло: HTML5-файл, знак «запрещено», урна).
  Картинка `position: fixed`, на всю ширину, непрозрачность ~12–18%, поверх — белёсый
  градиент-оверлей для читаемости контента.
- **Карточки:** белые (опционально лёгкий glass: `backdrop-filter: blur` + ~92% белого),
  скругление `20px`, мягкая тень `0 4px 24px rgba(80,70,160,.08)`, граница
  `1px rgba(0,0,0,.04)`.
- **Primary (индиго):** `#6c5ce7`, hover темнее; акцентные поверхности — градиент
  `#7b6cf6 → #6c5ce7`. Контрастит с зелёным фоном.
- **Success (лайм/салатовый):** `#a3e635`; мягкая подложка бейджей `#d9f99d`.
- **Danger (коралл):** `#fb7185` — «удалено» в диффе и ошибки.
- **Типографика:** системный стек (San Francisco / Segoe UI / Roboto) — без внешних
  шрифтов (не зависим от Google Fonts на Render, нет FOUT). Жирные заголовки,
  трекинг `-0.01em`.
- **Чипсы/бейджи:** пилюли с мягкой подложкой.
- **Иконки:** инлайновые SVG (~10 шт.) вшиты в разметку, без библиотек: лого, дроп,
  статусы (очередь/обработка/готово/ошибка), скачать, глаз-превью, ножницы.
- **Микроанимации:** transition на hover/выбор, fade-in карточек результата,
  скелетоны при обработке.

## Layout — двухпанельный воркспейс

**Шапка (на всю ширину, тонкая):**
- Слева: лого + «ClickTag Cleaner» + честный сабтайтл про чистку под требования
  программатик-DSP (Hybrid), убираем переходы по клику.
- Справа: мини-сводка по батчу чипсами (напр. `креосов: N`, `кликов вырезано: M`).
  Появляется после обработки.

**Левая колонка (~340px, фиксированная):**
- Компактная дропзона сверху (drag-and-drop + клик для выбора, `.zip`, до 50 МБ).
- Жирная индиго-кнопка `Обработать (N)` со счётчиком очереди. Состояния:
  disabled при пустой очереди; `Обработка…` + спиннер во время запроса.
- Список креосов: строка-карточка = иконка статуса (в очереди / обработка-скелетон /
  готово / ошибка), имя, размер `in → out`. Кликабельны, активный подсвечивается
  индиго-подложкой.
- Прилипший снизу блок `Скачать всё одним архивом` (активен при наличии готовых).

**Правая колонка (тянется) — деталь выбранного креоса:**
- Превью side-by-side в карточке: «Оригинал» vs «После очистки», два sandbox-iframe,
  размер из `adSize` (дефолт 320×480), кнопки «в новой вкладке» / «перезагрузить оба».
- «Что вырезано» — дифф-карточки (бейдж типа действия + строки `−` удалено / `+`
  заменено), переключатель файла-`<select>`, если текстовых файлов несколько.
  В светлой теме: красноватая подложка у удалённого, зеленоватая у заменённого,
  моноширинный код.
- Кнопка `Скачать {name}_cleaned.zip`.
- Пустое состояние, когда ничего не выбрано («выбери креос слева»).

## Флоу и юзабилити

1. **Кнопка запуска сохраняется** (по требованию пользователя): накидал пачку →
   жмёшь `Обработать`. Авто-запуска по дропу НЕТ.
2. **Скелетоны** в списке во время обработки (бэк отдаёт всё разом — настоящего
   пер-файлового прогресса нет, показываем общий скелетон до ответа).
3. **Ошибки — инлайн** в карточке/детали (`alert()` убираем полностью).
4. **Авто-выбор** первого готового креоса после обработки — сразу виден результат.

## Адаптив

- Десктоп — базовый сценарий.
- На узком экране (<900px) колонки схлопываются вертикально: список сверху, деталь
  снизу. Макет не разваливается, но мобайл не приоритет.

## Ограничения / риски

- Бэк возвращает весь батч одним ответом → реального пер-файлового прогресса нет,
  только общий скелетон. Настоящий стриминг-прогресс = правка сервера, вне этого
  редизайна.
- Фоновая картинка не должна вредить читаемости — отсюда низкая непрозрачность +
  оверлей + плотные карточки. Если контраст всё равно страдает — снижаем
  непрозрачность фона.
- Картинка `public/assets/bg-creo.png` уже положена в репозиторий (2.5 МБ; при
  необходимости можно пожать для скорости загрузки).
